# AGENTS.md

Instructions for agents (and future human contributors) working in this repository.
**Read this file before changing anything.**

## What this is

A minimal personal blog generated statically with Quartz v5. Four constraints, everything
else follows from them:

1. Documents are the only data layer — no database, no CMS, no extra structured data files.
2. Derived data (tags, listings, recent posts, reading time) exists only at build time.
3. Features are added through plugins, wired in `quartz.config.yaml`.
4. The site is static output; nothing in the frontend can write back to the data layer.

## The most important thing: posts are org-lite, not Markdown

**Write posts under `org/`, in org-lite syntax. Never write into `content/`.**

```
org/                <- the only source of truth, write posts here (.org)
content/            <- generated by the converter, do not edit
public/             <- build output, do not edit
```

- **org-lite is neither Markdown nor full Org mode.** It keeps a defined subset: headings,
  paragraphs, lists, checkboxes, inline formatting, scripts, entities, LaTeX, links, tables,
  property drawers, `#+NAME:` / `#+CAPTION:`, SRC/EXAMPLE/QUOTE/COMMENT blocks and footnotes.
- **Full Org features are not available**: TODO states, headline tags, timestamps,
  `SCHEDULED`/`DEADLINE`, macros, `#+INCLUDE`, table formulas, `VERSE`/`CENTER`/`EXPORT`
  blocks, anonymous footnotes. Those constructs are treated as plain text.
- Details live in **`docs/org/`** (see below). Do not assume Org mode behavior.

Upstream project: <https://github.com/WallyHao/org-lite>

## Writing a post

Create a `.org` file under `org/posts/`. The file name is the URL slug. Pages such as the
home page or the about page live at the root of `org/`.

```org
#+TITLE: Title
#+DATE: 2025-11-05
#+DESCRIPTION: One-sentence summary used by listings, search and og:description.
#+TAGS: quartz, architecture

Body text with *bold*, /italic/, _underline_, +strike+ and ~inline code~.

** A section

- list item
- [ ] todo
- [X] done

| Name  | Count |
|-------+-------|
| Apple | 3     |

#+BEGIN_SRC python
print("hello")
#+END_SRC
```

Metadata is converted into the YAML frontmatter Quartz expects:

| org metadata    | frontmatter   | Notes                                                              |
| --------------- | ------------- | ------------------------------------------------------------------ |
| `#+TITLE`       | `title`       | Falls back to the file name                                        |
| `#+DATE`        | `date`        | Falls back to the file mtime (generated files have no git history) |
| `#+DESCRIPTION` | `description` | Summary                                                            |
| `#+TAGS`        | `tags`        | Space or comma separated                                           |
| `#+DRAFT`       | `draft`       | `true` keeps it unpublished                                        |
| `#+UNLISTED`    | `unlisted`    | `true` hides it from listings, RSS and search                      |
| `#+ALIASES`     | `aliases`     | Old links that should redirect                                     |

Links **must use the `file:` prefix**, otherwise they are parsed as in-document anchors:

```org
[[file:posts/][All posts]]        -> /posts/
[[file:about.org][About]]         -> /about
[[file:notes.org::*Plan][Plan]]   -> /notes#plan
[[https://example.com][External]] -> external link
```

Any non-`.org` file under `org/` (images and so on) is copied to `content/` verbatim, so
relative paths work.

## Build and verify

Requires **Node.js >= 24.12** (org-lite requirement).

```bash
npm ci                                # first install
npm run org                           # org/ -> content/, conversion only
node scripts/org-to-md.mjs --check    # report only, write nothing
npm run preview                       # convert + serve on http://localhost:8080
npm run build                         # convert + build
npx tsc --noEmit                      # type check
npx prettier --check .                # formatting
```

Conversion warnings such as `unsupported`, `unclosed` or `orphan` mean the org syntax was not
recognized. **Do not ignore them** — either rewrite the construct into a supported one or
accept the degradation explicitly.

## Pipeline

```
org/*.org
  +- scripts/org-to-md.mjs        reads, parses, builds mdast, serializes
       +- vendor/org-lite/dist    the org-lite parser (upstream build output, do not edit)
       +- mdast-util-to-markdown  handles Markdown escaping and formatting
            |
content/*.md                      generated (.gitignore), with YAML frontmatter
            |
Quartz v5 plugin pipeline         transformers -> filters -> emitters -> HTML
```

`scripts/org-to-md.mjs` is a format translator only: it does not render pages, style
anything, or write outside `content/` (the `.org-to-md.json` manifest exists to prune stale
output).

## Do not

- Do not edit `content/`, `public/` or `.quartz/`; they are generated.
- Do not write Markdown into `org/`: `## heading`, `[text](link)`, fenced code blocks and
  GFM task syntax do not work there. Use `** heading`, `[[file:x.org][text]]` and
  `#+BEGIN_SRC` instead.
- Do not edit `vendor/org-lite/`; refresh it as described in `vendor/org-lite/README.md`.
- Do not add `content/` back to git, and do not restore `gitignore: true` in
  `quartz/util/glob.ts` (see core patches below).
- Do not add features that need to write back to the data layer (comments, likes). If
  persistence is required, use an external service.
- Do not delete `plugins/default-theme/`: it pins the first-visit theme to light in the
  `<head>`. Without it the site follows the OS dark preference. Change
  `options.theme` to alter the default.

## Core patches to Quartz

Three places only; merge them carefully when upgrading Quartz:

1. `quartz/plugins/pageTypes/404.ts` — mark the generated 404 page as `unlisted`, otherwise
   it shows up in "recent posts" and in search.
2. `quartz.ts` — register a custom layout condition `index` so `recent-notes` renders on the
   home page only.
3. `quartz/util/glob.ts` — `gitignore: false`. `content/` is generated and listed in
   `.gitignore`, but the build still has to read it; ignore rules come from `ignorePatterns`
   in `quartz.config.yaml` instead.

## Known limitations (intentional)

- Checkboxes have two states; `[-]` becomes `[ ]` plus a `<!-- partial -->` comment.
- `#+CAPTION:` becomes an italic paragraph, `#+NAME:` becomes an anchor; there is no figure
  numbering.
- `::25` line selectors and `::/regexp/` selectors are dropped from links.
- Ordered lists are renumbered by Markdown rules.
- Property drawers only contribute `ID` / `CUSTOM_ID`.
- Comment blocks are dropped.

The full list is in `README.md`.

## Commit conventions

- Use [Conventional Commits](https://www.conventionalcommits.org/): `feat:` / `fix:` /
  `docs:` / `refactor:` / `chore:`, optionally with a scope, e.g. `fix(theme): ...`.
- **Write commit messages in English.** Explain why in the body; do not restate the diff.
- One commit per concern. When a change touches a Quartz core patch, name the file and the
  reason in the body.
